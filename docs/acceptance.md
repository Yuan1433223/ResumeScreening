# 收尾验收与复核方式

本项目的验收范围是本地单用户作品集：使用合成样例、规则抽取与模拟外部服务，说明证据、人工决定和恢复机制。以下不是招聘效果或真实外部服务的验收结论。

| 展示成果 | 如何复核 | 自动验证 |
| --- | --- | --- |
| 判断回到简历原文 | 启动工作台，创建批次，打开一条有引用的结果，在“事实与原文证据”选择引用，查看同次评估保存的正文定位与高亮。历史记录没有快照时须重新分析。 | `tests/test_t8_review_extractor_consistency.py` 验证复核读取保存的事实与原文，不重新抽取；`tests/test_t16_closeout.py` 验证文件变化时旧版本仍可读取。 |
| 审批在进程中断后继续 | 离线演示先保存审批、模拟中断，再启动新 Python 进程从检查点恢复；复核页对保存成功但恢复失败的决定提供继续恢复。 | `test_approval_recovery_in_fresh_python_process`、`test_saved_approval_can_be_resumed_after_api_failure` 和 T1 恢复测试。 |
| 重试避免重复预约或通知 | 在排期页查看预约及模拟会议、通知记录，重复执行会复用结果。离线演示额外注入通知失败并重试。 | `test_retry_keeps_booking_and_successful_actions` 分别注入建会与通知失败；`test_interrupted_scheduling_reuses_confirmed_and_pending_bookings` 验证排期处理中断后的占位恢复。 |

## 运行离线演示

在项目根目录运行 `python demo/run_demo.py`，使用已存在的合成 PDF 和脚本内合成候选人，不访问模型或真实日历。演示会重建专用 `data/demo.db`、`data/demo.checkpoints.db` 并写入 `demo/output/`，请勿将业务数据放在这些演示路径中。完成后可打开 `demo/output/index.html` 查看流程和结果。

## 验证范围

- 自动测试使用隔离数据库与模拟服务；前端构建和本地浏览器已检查主要流程。
- “审批恢复”指已经保存的人工决定可由检查点继续，不表示批次后台任务在服务重启后自动续跑。服务启动会标记中断任务，重新分析由人工发起。
- 防重针对本地记录与模拟服务的当前实现；真实第三方接口需验证其幂等支持和失败语义，不能直接推断拥有端到端恰好一次的保证。
- 真实招聘数据、生产部署、真实日历或通知渠道不在此次验收范围。历史七份简历评测是小样本观察，不代表招聘决策准确率。
