# 收束检查清单（Checklist）

逐项核对；每项给出"证据"（命令输出/文件位置），不要凭印象打勾。命令以通用形态给出，按项目实际技术栈替换。

## 1. 收尾就绪度评估
- [ ] 全量测试通过（记录实际数量，如 `pytest -q` / `npm test`）。
- [ ] 生产构建通过（如 `npm run build` / 打包命令），无阻断性错误。
- [ ] 核心功能闭环可走通（列出端到端主链路）。
- [ ] 列出 ≥3 个可演示亮点（差异化能力，不是"用了某框架"）。
- [ ] 明确区分：工程层已就绪项 / 门面层仍缺项。
- [ ] 若存在功能或正确性缺口 → 停止收束，回到开发。

## 2. 减法与归位
- [ ] 列出根目录全部文件，逐个定性：保留 / 归位 / 删除。
- [ ] 临时冒烟、一次性脚本：删除前全仓搜索文件名与模块名，**零引用才删**。
  - 搜索示例：`grep -rn "<脚本名或模块名>" --include=*.{py,ts,tsx,md,json,yml}`。
- [ ] 说明类 md：过时则更新、重复则合并、无引用且无价值则删。
- [ ] 根目录不保留 `todo.md`/`REVIEW.md` 半成品；待办并入"已知边界"或 issue。
- [ ] 输出目录、缓存、临时副本（如 `%TEMP%`、`dist`、`__pycache__`）不入库。
- [ ] **红线**：`.env`、密钥、证书、含真实数据/PII 的目录未被改动且未入库。
  - 校验：`git check-ignore -v <敏感路径>` 逐条确认被忽略。

## 3. 协作入口（AGENTS.md 范式）
- [ ] 一句话项目目标 + 技术栈表。
- [ ] 目录职责速览（每层管什么）。
- [ ] 常用命令：测试 / 启动 / 构建 / CLI / 外部服务（MCP、worker 等）。
- [ ] 架构与核心约定（关键不变量：幂等键、状态机、证据/引用规则、身份/租户边界）。
- [ ] 改代码规则：测试必须全绿（写明确切数量基线）、新增功能配测试、数据红线、不破坏开关语义、数据访问单点边界。
- [ ] 评测/安全现状（指标、已知漏洞与防线、合规处理）。
- [ ] 已知边界与易错点（环境依赖、回退路径、易踩坑）。
- [ ] 全文事实与源码一致，无需求文档式背景铺陈。

## 4. README 事实更新
- [ ] 徽章：CI、测试数、许可证、技术栈（链接真实有效）。
- [ ] 一句话价值主张（说清解决什么问题、与"裸调大模型/人工"的差异）。
- [ ] 一条命令快速开始（容器优先；其次开发模式）。
- [ ] 能力亮点表（每条有文件/测试佐证）。
- [ ] 界面演示区（见第 6 节占位）。
- [ ] 数字全部实跑核对：测试数、指标、版本、延迟/成本。
- [ ] 无真实姓名/电话/邮箱等 PII（含历史叙述中的真名，需脱敏）。

## 5. 工程师导航
- [ ] 代码地图（精简）：入口 → 各业务层 → 数据/安全层 → 集成/部署，每层"关键文件/类 + 一句话职责 + 对外契约"。
- [ ] 一条端到端调用链（如：上传 → 处理 → 人工节点 → 外部动作）。
- [ ] 参数键字典（完整）：逐条从配置源码与 `.env.example` 提取，列「键 | 用途 | 默认值 | 出处 | 是否必填」。
  - 校验：字典条目数 = 配置源码暴露键数；默认值逐个比对，无默认值如实标注。
- [ ] 项目结构树与实际目录一致（新增模块、测试、部署件已同步）。

## 6. 门面素材占位
- [ ] 截图路径约定（如 `docs/screenshots/NN-<page>.png`），README 留引用占位。
- [ ] 视频/GIF 路径约定（如 `docs/video/demo.gif`）。
- [ ] 占位处明确标注"由维护者补充"，不生成任何图片/视频。
- [ ] 提示素材须使用合成/脱敏数据，禁止真实用户数据入镜。

## 7. 验证与交付
- [ ] 全量测试复跑通过（记录数量）。
- [ ] 构建复跑通过。
- [ ] Markdown：标题层级、表格、代码围栏闭合，内部链接/图片路径有效。
- [ ] 被删文件零残留引用（再次全仓搜索）。
- [ ] 参数字典与配置源码逐条一致。
- [ ] PII 扫描通过（手机号/邮箱/身份证/已知真名）。
- [ ] 输出交付说明：改动文件清单、验证结果与命令、仍需维护者手动完成的动作。
- [ ] 未获明确授权前，不执行 git add/commit/push/tag、不部署、不发布。
