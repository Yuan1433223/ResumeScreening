## 1. 并行 / 串行判定矩阵

| 改动对象 | 判定 | 说明 |
| --- | --- | --- |
| 共享同一文件（同一路由文件、同一 `repository.py`） | 串行 | 后包依赖前包改完的文件，避免合并冲突与口径漂移 |
| 目录独立（后端新模块 vs 前端新页面） | 并行 | 前提：跨目录只通过冻结的契约交互 |
| 同一数据口径（如漏斗 extracted 计数） | 串行 + 打回修根因 | 口径不定清楚，并行只会各自实现、各算各的 |
| 契约已冻结的端点（前后端） | 并行 | 前端按契约 mock，后端按契约实现，各自验收 |

判定口诀：**问"两个包会不会改同一个文件 / 同一个口径"——会就串行；不会且契约已冻就并行。**

## 2. 契约冻结清单格式

主控在派工前冻结；子代理不得擅自改契约，要改回到主控重新冻结。

```
契约名：<SSE 进度 / Dashboard 聚合 / auth>
端点路径：<METHOD /path>
请求：<JSON 字段表：字段 | 类型 | 必填 | 空值语义>
响应：<JSON 字段表：字段 | 类型 | 空值语义>
事件协议：<SSE 事件序列 / 错误码 / 心跳>
验收：<哪条测试 / 哪个批次编号覆盖>
```

本项目已冻结的真实契约：

- **SSE 进度契约**：事件序列 `connected → progress(多次) → done | error`，心跳 `ping`；前端 SSE 断线后转轮询兜底，不丢进度。
- **Dashboard 聚合契约**：`kpis`（总量 / 成功 / 待复核 / 失败）、`score_distribution`（分桶计数）、`funnel`（extracted 口径——按 assessments 去重，不是按 runs 计数；这是两轮修复后定死的口径）。
- **auth 契约**：`AUTH_ENABLED` 默认关；关时单用户直通；开时单用户登录；`org_id` 列预留但本阶段不接多租户逻辑。

## 3. 本项目三包真实拆解表

| 包 | 范围 | 新增测试 | 验收数字 | 为下阶段预留的接缝 |
| --- | --- | --- | --- | --- |
| P0 门面冲刺 | 复核端点 bug 修复；README 首屏；5 张合成截图；logo/favicon；Dockerfile+compose；LICENSE MIT；tag v0.1；eval 脱敏聚合入库 | 护栏基线 | pytest 99 全绿；容器起得起 | eval 只做脱敏聚合 → P2a PII 加密 |
| P1 体验与工程 | dict→SQLite 落库；SSE 进度；上传魔数+20MB+DOCX；Dashboard 聚合；trace document_id 过滤；前端看板/Trace 页/8 维雷达/SSE+轮询兜底 | 32（99→131，含 1 xfail） | pytest 131；build 通过 | TaskStore ABC；repository 聚合边界 |
| P2a 安全可信 | quote↔value 一致性修复（xfail 转真）；GitHub Actions CI；PII 四件套；AUTH_ENABLED 默认关；org_id 列预留 | 44（131→175） | pytest 175 全绿；CI 绿；敏感路径被 ignore | org_id 列；AUTH 开关 |

工时直觉：测试护栏 0.5 天；前端新页 1 天；加密 / 红线类加固 1–2 天。

## 4. 派工任务书模板与口径打回示例

```
任务：<一句话>
实体与路径：<改哪个文件 / 目录，写全，不写"相关那几个文件">
契约：<引用已冻结的契约名；未冻结的先冻结再派>
禁止项：<不 commit / 不截图 / 不改 README / 不动 .env 与真实数据>
验收：<pytest 基线 N 不得退化，本包新增 M；build 通过>
回收：主控亲自重跑验收命令，不引用执行者自报数字。
```

口径缺陷打回示例：漏斗 extracted 第一轮按 `count(runs)` 翻倍 → 打回按 runs 去重 → 数字仍不一致 → 打回按 assessments 去重才定。**口径问题不算"做完了"，必须修到验收命令的数字自洽；冒烟发现口径缺陷就打回修根因，不接受"先这样、回头再说"。**
