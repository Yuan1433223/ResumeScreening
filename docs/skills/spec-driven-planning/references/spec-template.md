## 1. 使用说明

- 一个阶段一节；每节必须能被一条验收命令判定"做完 / 没做完"。
- 占位符 `<...>` 按项目替换；没有的小节删掉，不强行保留。
- 数字（测试数、基线、版本号）写死，不写"若干""视情况"。
- DoD 每条都是可勾选项；勾不出来的条件（如"体验更好"）退回成可测量口径。

## 2. 单阶段规格骨架

```markdown
## P<n>：<阶段名>（约 <工时直觉>）

### 目标
<一句话：这一段结束后系统具备什么能力>

### 非目标
<这一段明确不做什么；防止范围漂移>

### 范围
**做什么**
- <具体改动 / 新增能力>
**不做什么**
- <这一段忍住不碰的东西>

### DoD 完成定义（可验证）
- [ ] <一条可由命令 / 测试判定的条件>
- [ ] <基线数字不退化>

### 验收命令
- `pytest -q`（基线 <N> 不得退化，本包新增 <M>）
- `npm run build`
- 必要时合成数据冒烟（不截图）

### 数据红线
- <本项目固化红线，逐阶段重申>

### 风险与回滚
- <最大风险>；<出问题回退到哪一步 / 哪个 tag>

### 阶段依赖
- 前置：<P<n-1> 或某冻结契约>
- 为下一阶段预留的接缝：<如 TaskStore ABC / repository 聚合边界 / org_id 列>
```

## 3. 本项目真实填充示例

### P0：门面冲刺（约 1–2 天）
- **目标**：仓库从"能跑的代码"变成"可对外演示的门面"。
- **非目标**：不改核心评分 / 工作流逻辑；不接真实简历。
- **做什么**：复核端点 bug 修复；README 首屏；5 张合成数据截图（素材用合成数据）；logo / favicon；Dockerfile + compose；LICENSE MIT；tag v0.1；eval 脱敏聚合入库。
- **不做什么**：不做多租户；不接真实邮件 / 日历。
- **DoD**：全量 pytest 全绿（99 测试基线）；前端 build 通过；容器一条命令起得起。
- **数据红线**：截图与入库 eval 聚合不含真实姓名 / 电话 / 雇主。
- **接缝**：eval 入库只做脱敏聚合，为 P2a 的 PII 加密留位置。

### P1：体验与工程（约 2–3 天）
- **目标**：任务状态可见、上传可用、看板可看。
- **做什么**：任务内存 dict → SQLite 落库（TaskStore ABC 接缝）；SSE 进度端点；上传魔数校验 + 20MB 上限 + DOCX 支持；Dashboard 聚合端点；trace document_id 过滤；前端 recharts 看板 / Trace 页 / 8 维雷达图 / SSE + 轮询兜底。
- **不做什么**：不做鉴权；不做多用户。
- **DoD**：pytest 99 → 131（含 1 xfail）；前端 build 通过；SSE 断线后轮询兜底不丢进度。
- **接缝**：TaskStore 以 ABC 暴露、SQLite 是首个实现；repository 聚合边界为 P2a 的加密 / 红线查询预留。

### P2a：安全可信（约 1–2 天）
- **目标**：从"单机自用"加固到"可公开演示且不泄露 PII"。
- **做什么**：注入漏洞 quote↔value 一致性修复（原 xfail 转真测试）；GitHub Actions CI；PII 四件套（Fernet 加密 / 上传提示 / purge 保留期 / `export --redact`）；`AUTH_ENABLED` 默认关、单用户认证、org_id 列预留。
- **不做什么**：不做完整 RBAC；org_id 只加列不接多租户逻辑。
- **DoD**：pytest 131 → 175 全绿（xfail 清零）；CI 绿；真实简历目录 / `.env` / `data/` 被 gitignore 且未入库。
- **接缝**：org_id 列与 `AUTH_ENABLED` 开关为后续多租户预留，本阶段不启用。

## 4. 数据红线（本项目逐阶段重申）

- 真实简历目录、`eval/labels`、`.env`、`data/`：绝不入库、绝不入镜（截图 / 日志 / README）。
- 演示 / 冒烟一律用合成或脱敏数据。
- 校验：`git check-ignore -v <敏感路径>` 逐条确认被忽略；截图与日志中搜不到真实姓名 / 电话 / 雇主。
- 任何阶段包若产出越界素材（如子代理私写的 README 门面草稿），识别后清除或上报，不带入下一阶段。
