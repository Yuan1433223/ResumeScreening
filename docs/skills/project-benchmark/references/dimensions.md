每维 0-5 分。打分时**先按锚点定档，再写一句依据**（对应到竞品仓库现象或自家 `file:line`），不许凭感觉给分。同一张表内本项目与竞品对齐同一把尺子。

## 1. 门面第一印象

访客 30 秒打开 README / 仓库首页的观感，决定"要不要往下看"。

| 分 | 锚点 |
| --- | --- |
| 0 | 无截图、无 logo、README 只有几行字或纯代码转储 |
| 1 | 有一句项目描述，但无任何视觉素材 |
| 2 | 有 logo + 至少一张截图 |
| 3 | 截图成组 + 徽章（CI/license/技术栈）+ 快速开始 |
| 4 | GIF 演示 + 可点的在线 demo + 徽章齐全 |
| 5 | 独立文档站（docs site）+ 介绍视频/播客式叙事 |

- **本项目对照落点**：起步约 2 分（有 README 与能力清单，截图/GIF/demo 待补）；P0 冲刺目标补到 3-4 分。
- **标杆案例**：Dify（文档站 + 视频 + 在线 playground）、vercel/chatbot（一键部署按钮 + 截图）。

## 2. 前端视觉与 Agent 可观测交互

Agent 项目的"过程可见性"比传统 CRUD 更关键：用户能不能看清模型在想什么、卡在哪、哪一步可调。

| 分 | 锚点 |
| --- | --- |
| 0 | 无过程展示，只有最终结果一坨文本 |
| 1 | 结果带简单状态文字（"处理中…"） |
| 2 | 有日志列表 / 步骤流水（平铺） |
| 3 | 关键中间产物可点开（抽取结果、证据片段可见） |
| 4 | trace 树 / 时间线：节点按层级展开，每步输入输出可见 |
| 5 | 时间旅行（回退重放某步）或内联审批/内联工具卡片 |

- **本项目对照落点**：3 分档（证据引用可回溯到原文切片、HITL 人工节点可见）；缺 trace 树与内联交互，是 P1 重点。
- **标杆案例**：Langfuse（分层 trace 树，span 点开看 token/耗时）、assistant-ui（内联工具卡片，工具调用就地渲染成卡片）、langchain-ai/agent-chat-ui（时间旅行，可回退任意节点重跑）、Dify（reactflow 画布上节点按状态着色）、OpenHands（四面板 Canvas：文件/终端/浏览器/对话同屏）。

## 3. 功能广度与产品闭环

从"一个能跑的脚本"到"一个别人能走完的产品流程"的完整度。

| 分 | 锚点 |
| --- | --- |
| 0 | 单脚本，输入输出硬编码 |
| 1 | 可换输入跑通，但无持久化/无配置 |
| 2 | 有输入→处理→输出主链路，参数可配 |
| 3 | 多角色/多状态闭环（含人工节点、失败分支） |
| 4 | 有持久化、历史记录、可复用会话/任务 |
| 5 | 对外协议齐全（API/MCP/CLI），第三方可直接接入 |

- **本项目对照落点**：4 分档（简历上传→筛选→HITL→证据引用闭环，有持久化与崩溃恢复）；5 分档已有 MCP 暴露，属真实优势，对标时不要自我否定。
- **标杆案例**：Dify（应用全链路：编排→发布→API→观测）、OpenHands（编码任务端到端闭环）。

## 4. 架构与落地就绪

代码结构是否撑得住"明天再加一个需求/换一个模型"。

| 分 | 锚点 |
| --- | --- |
| 0 | 单文件千行，无分层 |
| 1 | 粗分目录，但边界混乱 |
| 2 | 分层清晰（入口/工作流/数据/能力），依赖单向 |
| 3 | 编排与能力解耦（换模型/换解析器不动主流程） |
| 4 | 有状态机/开关语义、幂等、回退路径设计 |
| 5 | 可容器化部署、配置集中装配、迁移与可观测齐备 |

- **本项目对照落点**：3-4 分档（基于 LangGraph 编排、节点分层、开关语义与证据不变量明确）。
- **标杆案例**：Langfuse（自托管 + 云双层部署）、OpenHands（Docker 沙箱隔离执行）。

## 5. AI 工程能力

不只是"接了个大模型"，而是"知不知道自己准不准、花多少钱"。

| 分 | 锚点 |
| --- | --- |
| 0 | prompt 写死，无评测 |
| 1 | 有人工看效果，无指标 |
| 2 | 有一份 eval 脚本跑过一次 |
| 3 | 有固定评测集 + 核心指标（P/R/F1 或成功率）+ 口径记录 |
| 4 | 评测可持续复跑、分环节归因、有 trace/成本记录 |
| 5 | 评测进 CI、回归自动报警、成本/延迟有看板 |

- **本项目对照落点**：3-4 分档（真实简历 eval 对照、F1 0.36/0.73 分档记录、证据可回溯）——这是相对多数"玩具 Agent"的硬优势。
- **标杆案例**：Langfuse（trace + 评分 + dataset 评测闭环）、Dify（标注与评测集管理）。

## 6. 工程化与可信度

让别人敢信、敢接手、敢复现。

| 分 | 锚点 |
| --- | --- |
| 0 | 无测试、无 CI、跑不起来靠口口相传 |
| 1 | 有零星测试 |
| 2 | 测试若干但不全绿 / 无 CI |
| 3 | 测试全绿（记录数量）+ 有 README 快速开始 |
| 4 | CI 跑测试 + 构建 + 目录/配置导航齐全 |
| 5 | 覆盖率门禁、预提交钩子、版本化配置与变更日志 |

- **本项目对照落点**：3-4 分档（175 passed 测试 T1-T15 编号、一条命令启动、协作手册）；CI 徽章与覆盖率是 P0 门面可补项。
- **标杆案例**：CopilotKit、assistant-ui（模板 + CI + 版本发布规范）。

## 7. 社区与叙事

开源项目的"被发现、被信任、被贡献"势能。**对作品集项目此维天然低分，不必硬追**。

| 分 | 锚点 |
| --- | --- |
| 0 | 私有/无人知晓 |
| 1 | 公开仓库，无 star |
| 2 | 个位数 star，无 issue 讨论 |
| 3 | 有持续 push + 少量 star/关注 |
| 4 | 文档站 + 社区渠道（discord/讨论区）+ 真实用户 issue |
| 5 | 被媒体/大会引用、有外部贡献者与生态插件 |

- **本项目对照落点**：0-1 分档（作品集阶段不追求）；报告中如实写，不刷数据、不编 star。
- **标杆案例**：Dify（~155.8k★）、OpenHands（~88k★）、Langfuse（~34.9k★）——star 数字均为第三方快照（2026-08/09），引用时标注日期与 ±误差。

---

> 评分纪律：每维给分后必须落一句依据；自家优势分（第 3/5/6 维）往往高于纯门面项目，这是真实家底，不是打分偏袒。
