# 对标报告模板（Report Template）

最终产物是**单文件 HTML**（本项目实例 `docs/competitive-benchmark.html`）：全部 CSS/SVG 内联、主色墨青 `#1f5f54`、**不用紫蓝渐变**、雷达/漏斗/时间轴用手写内联 SVG，不引外部图库、不生成图片。复制本结构，逐节按"填写要点"写；没有的小节删掉，别凑数。

## 1. 执行摘要

- **填写要点**：KPI 数字先行，3-5 行说清"我是谁、排在哪、下一步先干什么"。开头给总分/中位分结论 + 3 条最该做的 P0。
- **实例引用**：`competitive-benchmark.html` 顶部先甩核心数字（七维总分、与同类中位分差、175 测试、eval F1 档位），再一句话给 P0 结论。

## 2. 对标对象与取证说明

- **填写要点**：列出 A 路（同赛道竞品）与 B 路（工程/门面标杆）分别取了哪几个仓库；写清两类取证差异——A 路重功能与 license，B 路重前端范式与交互；单列**未核实清单**（API 403、抓不到的项）。
- **实例引用**：A 路 srbhr/Resume-Matcher、pyresparser、sliday/resume-job-matcher、liangdabiao/resume-matcher-agent-cn、ziggy-xzding/ResumeInterviewAnalyzer；B 路 Dify/Langfuse/OpenHands/suna/assistant-ui/CopilotKit/vercel chatbot/agent-chat-ui。GitHub API 直连 403 的部分明确写"第三方快照/未核实"。

## 3. 竞品总览表

- **填写要点**：表头固定 `仓库 | star(取证日期) | 主语言/栈 | 前端形态 | license | 最近活跃度 | 门面三要素(截图/GIF/demo)`。star 一律带取证日期与 ±误差；license 只写查到的，查不到写"无 LICENSE"。
- **实例引用**：Resume-Matcher 28.5k★ Apache-2.0、pyresparser 958★ GPL-3.0 且停更、resume-job-matcher 272★ 无 LICENSE、liangdabiao 163★、ziggy-xzding 7★（LangGraph 11 节点）；Dify ~155.8k★、Langfuse ~34.9k★、OpenHands ~88k★、suna ~20.2k★、assistant-ui ~12.3k★、CopilotKit ~37.5k★、vercel chatbot 20,970★、agent-chat-ui ~3.2k★——均 2026-08/09 快照。

## 4. 七维评分矩阵

- **填写要点**：热力表（行=竞品，列=七维，单元格=0-5 分 + 一句依据）+ 雷达图（本项目 vs 同类中位 vs 一个 B 路标杆，三条线）。评分锚点严格对齐 `dimensions.md`。
- **实例引用**：`competitive-benchmark.html` 用内联 SVG 画雷达；热力单元格墨青深浅表示分值高低。

## 5. 自家家底优势

- **填写要点**：只写**可指到 `file:line` 或实跑输出**的优势；逐条对比"多数玩具项目缺什么、我有什么"。这一节是防止对标时自我否定的锚。
- **实例引用**：证据引用可回溯到原文切片（偏移由程序计算）、HITL + 崩溃恢复、真实简历 eval 对照（F1 0.36/0.73）、MCP 对外暴露、175 passed 测试（T1-T15）。

## 6. 前端标杆拆解

- **填写要点**：范式表 `标杆 | 范式 | 它怎么解决 | 链接`，**只用文字 + 链接描述界面，绝不臆造图片**（不截图、不生图）。一行说清"这个交互为什么值得抄"。
- **实例引用**：Langfuse 分层 trace 树、assistant-ui 内联工具卡片、agent-chat-ui 时间旅行、Dify reactflow 节点着色、OpenHands 四面板 Canvas——每条配仓库/文档链接。

## 7. P0 / P1 / P2 差距清单

- **填写要点**：三档分组，每条 `差距 | 视角(门面/落地) | 工时直觉 | 证据 file:line`。P0=1-2 周门面冲刺，P1=体验升级，P2=落地深化。视角必须二选一标注，别混。
- **实例引用**：门面视角差"截图/GIF/在线 demo/CI 徽章"；落地视角差"trace 树、内联审批、评测进 CI"。

## 8. 逐页 / 逐模块改造方案

- **填写要点**：按前端页面或模块逐个写"现状 → 改成什么 → 抄哪个标杆 → 工作量"。与第 7 节对应，但落到具体位置。
- **实例引用**：对话页加内联工具卡片（抄 assistant-ui）、过程页加 trace 树（抄 Langfuse）、README 加 GIF 与一键部署（抄 vercel chatbot）。

## 9. 落地就绪清单

- **填写要点**：区分"作品集门面就绪"与"客户真用就绪"两张勾选项；每条给可验证标准。
- **实例引用**：门面就绪=有截图/demo/徽章/测试数可点；落地就绪=鉴权、PII 脱敏、容器化部署、成本与延迟记录。

## 10. 路线图时间轴

- **填写要点**：横向时间轴（手写 SVG），P0(1-2 周) → P1(3-6 周) → P2(之后)，每段列里程碑，不排具体日期。
- **实例引用**：`competitive-benchmark.html` 内联 SVG 时间轴，墨青主色分段着色。

## 11. 面试话术

- **填写要点**：把对标结论翻成 3 句"被问到怎么答"——差异化优势一句、主动承认的差距一句、下一步路线一句。话术要和报告数字一致。
- **实例引用**："我不是又一个简历 matcher——我做了真实简历 eval、证据可回溯、HITL 崩溃恢复；门面确实是短板，P0 两周补 demo。"

## 12. 克制清单（应保持不做）

- **填写要点**：明确写"哪些对标项看着诱人但本阶段不做"及理由（撑爆范围 / 偏离定位 / 作品集阶段无意义）。这一节防止对标变成无限加需求。
- **实例引用**：不刷 star、不做多人协作/租户系统、不上线付费、不追社区运营（第 7 维天然低分不必硬补）。

## 13. 分组来源清单

- **填写要点**：按 A 路竞品 / B 路标杆 / 第三方快照分组列出每条事实的来源 URL；第三方站标注取证日期与 ±误差；"未核实"项单列。
- **实例引用**：GitHub API 优先；API 403 时 raw.githubusercontent.com + 仓库 HTML 页；starhistory 类快照注明日期。**star/技术栈/license 严禁编造**——查不到就写"未核实"。

---

> 产出纪律：单文件、内联 CSS/SVG、墨青 `#1f5f54`、无紫蓝渐变、无外部图库、不生成图片；所有数字带取证日期，可回查到来源 URL。
