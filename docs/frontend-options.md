# 前端展示取舍

核对日期：2026-10-28。结论：作品集收尾不需要更换整个前端；若补一次视觉整理，优先借鉴成熟后台的视觉体系和人工复核布局，保留现有 API 与业务页面。

## 开源参考

| 项目 | 官方信息 | 本项目适合借鉴 | 直接替换的代价与判断 |
| --- | --- | --- | --- |
| [Shadcn Admin](https://github.com/satnaing/shadcn-admin) | MIT；Vite、TypeScript、shadcn/ui、TanStack Router；提供侧栏、表格等后台页面 | 导航层级、列表密度、工具栏、状态标签、卡片与表单的一致性 | 最适合门面参考。但当前应用是原生 CSS 与 hash 路由，整仓迁移会带入新的样式和路由体系；建议只借鉴布局和必要组件。 |
| [Agent Inbox](https://github.com/langchain-ai/agent-inbox) | MIT；面向 human-in-the-loop；GitHub 标注于 2026-09-20 归档 | 待处理队列、人工审批面板、任务上下文与处理动作的分区 | 场景最贴近，但已归档，适合作为交互参考。依赖 LangGraph deployment API 及规定的 interrupt 输入输出协议，当前 FastAPI 不是即插即用。 |
| [Agent Chat UI](https://github.com/langchain-ai/agent-chat-ui) | MIT；Next.js；连接带 messages 状态的 LangGraph server | 工具结果和侧边产物展示、运行状态反馈 | 当前业务是批次、证据、审批和排期，没有聊天 messages 契约。改成聊天入口需要重做数据与服务适配，不符合收尾目标。 |

来源均为对应仓库 README、技术栈说明、许可证标识及归档状态；这是适配性判断，不是对三个项目视觉质量的客观排名。复用代码时保留对应许可证与署名说明。

## 必要性判断

| 投入 | 对作品集的收益 | 收尾决策 |
| --- | --- | --- |
| 精简 README、架构图、直接展示已有截图 | 访客快速理解问题、职责和工程取舍 | 本轮完成 |
| 统一间距、字体、表格、标签、加载与空态 | 提升成熟感，降低“临时界面”的观感 | 可选，严格限于现有页面 |
| 重排批次页与复核页的信息层级 | 让原文、事实、机器建议、人工决定更容易区分 | 可选，优先于增加看板 |
| 换成完整后台项目 | 可以统一视觉，但迁移路由、状态和组件成本较高 | 当前不采用 |
| 改成聊天式 Agent 门面 | 容易突出对话，却弱化证据审核和批量任务 | 当前不采用 |
| 新增工作流编辑器、自动规划、实时思考面板 | 增加演示复杂度，不能证明现有实现更可靠 | 不进入本项目收尾范围 |

如果以后只安排一次前端整理，范围限定为批次页、复核页及共用导航：采用一致的中性后台视觉；复核页保持原文与证据并列；将机器建议、信息缺失和人工审批明确分开。unknown 不应仅用与 0 分相同的视觉表示。运行状态展示可用已有批次进度，不伪装成逐 token 模型推理或完整节点追踪。

无需为展示重新制造企业数据、接入真实日历或扩大模型评测。现有界面截图作为历史实现佐证；新截图只在实际前端发生变化后更新。
