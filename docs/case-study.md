# 项目介绍与设计取舍

这份材料用于作品集和面试介绍。当前架构以 [architecture.md](architecture.md) 为准，评测数字以注明日期的历史结果为准。

## 简短介绍

ResumeScreening 是从企业 AI Agent 面试场景重构而来的简历筛选辅助工作流。项目围绕一个具体岗位，将解析、模型事实抽取、引用校验、规则评分、人工审批及模拟排期串联起来。模型输出需要能够定位到简历原文；程序计算评分与排期，人工保留批准权。工程重点是 LangGraph 持久化暂停与恢复、审批消费时序、预约及外部动作幂等，以及配套的 FastAPI / React 工作台和评测方法。

## 面试时展开的三个设计

### 为什么限制模型的职责

把模型用于自然语言事实抽取，将阈值、分档、排序和副作用交给程序，便于定位错误来源。模型返回页码和引文，字符偏移由程序计算，避免模型自己生成看似精确的位置。缺失信息保留 unknown，不把简历沉默直接解释成不满足条件。

证据位置合法不代表语义正确，因此人工复核仍是主链路的一部分。当前词表检查用于缓解明显越权贴档，不能声称完成语义证明或全面防注入。

### 为什么审批先持久化再恢复

人工决定与图恢复是两个步骤。先写入审批，图成功恢复后再标记 consumed，能覆盖“审批写入后进程退出”的窗口；若图已经结束，重放只补消费和运行收尾。T1 测试以故障注入验证这些边界。

这个机制验证的是恢复时序；当前前端幂等键及评估修订版本隔离仍有不足，不把服务层机制延伸成完整生产审批承诺。

### 为什么排期独立于单份简历分析

逐份解析完成时立即占槽，会把处理先后顺序带入有限时段分配。将排期放在批次入口，统一按分数和岗位维度排序，再原子占槽，能表达全局资源竞争。建会与通知用 mock 保留失败动作重试的验证，不依赖个人项目接入企业系统。

## 验证证据

- 当前回归基线：2026-10-28，175 项测试通过，前端构建通过。范围为隔离测试和构建，不含 Docker 构建或真实日历验收。
- 历史抽取对照：2026-09-18，7 份 dev 简历，规则 F1 0.36、模型 F1 0.73。仅为当次事实抽取观测；原始真实数据不公开，模型完整配置未随摘要保留。
- 工作台截图：展示批次结果、原文与事实并列、事实引文高亮和模拟排期。当前复核重抽取限制单独披露，不称为完整评分快照回放。

## 收尾决定

项目完成到企业场景工程案例的范围：保留代码、架构、测试与历史评测材料。没有真实业务方和持续数据源，因此停止沿招聘平台方向扩展，不为补齐产品叙事继续制造业务模拟。前端只保留有限视觉整理的可选空间，具体取舍见 [前端参考](frontend-options.md)。
