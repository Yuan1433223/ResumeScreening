01执行摘要

三句话结论 + 证据链。

后端工程素养已经超过绝大多数同赛道玩具项目。8 节点 LangGraph 图（parse→extract→validate→screen→score→review(interrupt)→apply→report）、模型只回页码+原文引文且由程序计算字符偏移、validate 节点校验一致性、SqliteSaver 检查点 + 幂等审批 + 故障注入测试、真实标注 eval（规则 F1 0.36 vs 模型 0.73）、成本/延迟 P50·P95 逐简历落 trace、MCP 薄代理对外暴露 8 tools/2 resources/1 prompt——在 14 个取证仓库里，这套证据链与 HITL 严谨度只有 sliday 与 Langfuse 同档意识。

失分全部集中在"看不见"的地方。无 logo、无截图、无 demo GIF、无 badge、无 Docker、无 LICENSE、无认证；docs/ 整个目录未被 git 跟踪，eval 数据被 gitignore——GitHub 访客只能读到 README 里的文字，看不到任何运行证据。门面维度自评 1.5/5，社区叙事 1/7 维里最低。这不是能力问题，是"想不想做"的问题：7 star 的同栈项目 ziggy 都有 banner + 架构图。

结论：门面冲刺 1–2 周（P0，20–30h）即可把第一印象翻篇——README 首屏三段式、5–8 张真实截图、30s demo GIF、Dockerfile+compose、MIT LICENSE、修掉 app/api.py 约 284 行硬编码 mock 的演示穿帮 bug。落地件（认证/Postgres/队列/对象存储/PII）按 P2 清单在 1–3 月渐进，不必在求职前一步到位。

双视角原则：下文每条差距都标注归属——门面=面试官第一印象与 demo 观感；落地=真实部署与生产就绪；二者兼得的标门面+落地。

05本项目真实家底（优势，诚实放大）

六条读码核实的差异化资产——面试官在乎什么、在 14 个仓库里排在哪。

1 · 证据引用可回溯

模型只回页码+原文引文，字符偏移由程序计算，validate 节点校验引文与原文一致，前端点击事实→原文 mark 高亮。

面试官在乎：LLM 招聘最大的风险是幻觉式打分，这套链把"评分"和"简历原文"焊死。在 14 个仓库里与 sliday"先引证据再打分"铁律同构——而我们多了程序算偏移 + UI 联动，sliday 只是 prompt 约束。

2 · HITL 崩溃恢复 + 幂等审批

review 节点 LangGraph interrupt + SqliteSaver 检查点；审批 request_id 幂等入库、VersionConflictError 防版本冲突；resume_run 消费未消费审批，有故障注入测试。

面试官在乎：suna 的 Change Request 审批门禁是产品叙事，我们是"进程崩了审批不丢"的工程事实。OpenHands 只敢声明单机单人，我们有恢复语义。

3 · 诚实的标注 eval

7 份 dev + 3 份保留 test：规则 F1 0.364 vs 模型 F1 0.727（P.78/R.68），证据定位有效率 100%，model 转人工率 71.4%、P95 66.7s；temperature=0 两天重跑仍有 0.67→0.88 波动。

面试官在乎：14 个仓库里只有 Langfuse / sliday 有类似 eval 意识，且我们敢公开记录波动与口径争议——这是稀缺信任状。

4 · MCP 薄代理

mcp_server.py 暴露 8 tools / 2 resources / 1 prompt，stdio + streamable-http 双传输，薄代理本机 FastAPI 单一事实来源，零业务逻辑重复，官方客户端全链路验证。

面试官在乎：踩中 2025–2026 Agent 生态热点；CopilotKit 的 AG-UI、assistant-ui 的 LangGraph runtime 都在证明"可被外部 Agent 编排"是主流方向。

5 · 工程纪律

99 测试全绿（tests/ 11 文件、96 test 函数参数化展开）、requirements 锁版本、Pydantic SecretStr、429/5xx 重试而 4xx 不重试、一次格式纠正、TS strict。

面试官在乎：对照 ziggy（7 star）与 sliday（无 LICENSE），工程纪律是简历筛选岗的硬通货；缺的只是把它跑在 CI 上。

6 · 领域真实 + 三态哲学

特定海外岗位 8 维评分表；硬条件 pass/fail/unknown 三态——"沉默≠通过"，定位失败宁可转人工不硬凑；单份失败不阻断批次。

面试官在乎：与 sliday gate 哲学不谋而合，但我们有完整工作流与证据校验；model 转人工率 71.4% 是特性不是 bug。

认证

FastAPI JWT/会话 + httpOnly cookie 登录页；简历是 PII，至少要有登录。对照 OpenHands 明确声明单机单人——我们必须登录的差异要讲清。

面试怎么讲："OpenHands 敢不做认证是因为它跑代码不碰个人隐私；简历是 PII，认证是底线不是加分项。"

Postgres + Alembic

SQLite 保留为开发默认，生产切 Postgres，checkpointer 换 PG 版；Alembic 管迁移（现在 repository 内建表）。

面试怎么讲："SQLite WAL 做开发默认是对的，换 Postgres 是为并发写与 checkpointer 共享。"

任务队列 / 对象存储 / PII

ARQ/RQ+Redis 替 daemon Thread；简历落 MinIO/S3 + 签名 URL；at-rest 加密、日志脱敏、保留期与级联删除（clean 已有级联基础）。

面试怎么讲："长任务从线程内存 dict 迁到可取消可重试的队列，是从 demo 到产品的关键一跳。"

Sentry / OTel

trace JSONL 接 OpenTelemetry 或自托管 Langfuse（compose 加一个服务），成本看板；前端接 @sentry/react。

面试怎么讲："后端可观测性我已经做了一半（每简历一条 trace），缺的只是把它接到标准后端。"

11面试讲解亮点话术（6 个技术故事）

每段 2–3 句，可直接背诵。

故事 1 · 证据链防幻觉

"模型只允许返回页码 + 原文引文，字符偏移由程序计算而不是模型自己报，validate 节点再校验引文与原文一致；前端点评分能高亮原文。定位失败宁可转人工不硬凑——model 转人工率 71.4% 是特性不是 bug。"

故事 2 · 三态 unknown 哲学

"硬条件是 pass/fail/unknown 三态，沉默不等于通过。这和 sliday 的 gate 哲学不谋而合，但我们多了证据校验和完整工作流——unknown 一律转人工，不替招聘方拍脑袋。"

故事 3 · 崩溃恢复与幂等

"LangGraph interrupt + SqliteSaver 检查点，审批幂等入库后再恢复；我写了故障注入测试，证明崩溃窗口不丢审批、END 节点不重放。"

故事 4 · 诚实 eval

"7 份真实简历人工标注，规则 F1 0.36 vs 模型 0.73；temperature=0 两天重跑仍有 0.67→0.88 波动，于是固定测试集、记录模型版本与日期、3 份 test 保留不调参。"

故事 5 · MCP 薄代理

"8 tools / 2 resources / 1 prompt 全部 HTTP 复用 FastAPI 单一事实来源，MCP 层零业务逻辑，官方客户端验证全链路——它能被外部 Agent 编排，而不是又造一个孤岛。"

故事 6 · 并发与缓存工程

"OCR 长图 250s/张，pages 缓存命中 0s；连接级 RLock + 图执行锁 + 后台线程串行批次，单份失败不阻断；成本/token 逐简历落 trace。"

12应保持不做的事（克制清单）

  • 不要上 Next.js 重写。SPA 工作台无 SSR/SEO 需求，重写是纯损耗；保留 Vite+React18。
  • 不要装 assistant-ui / CopilotKit。它们是聊天范式，本产品是工作台；只借"工具调用内联卡片、内联审批、状态直显"三个范式自己实现，保持零重依赖、每行代码可讲清。
  • 不要为加功能而破坏证据链严谨性。embedding 预筛、语义匹配可以加，但"先引证据再打分"的铁律不动。
  • 不要把真实简历推进公开仓库。截图/GIF 一律用 demo 固定种子合成数据；eval 只入库脱敏聚合数字。
  • 不要急着泛化岗位。单岗位垂直定位（海外钢结构/MiC）是叙事支点，多岗位 JD 管理是 P2，不是现在。
